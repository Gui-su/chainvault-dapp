------------------------------------------------
一、作品简介
------------------------------------------------
ChainVault 是一个基于区块链的数字版权保护与交易平台（DApp），面向数字艺术、音乐、文学三类作品，提供"确权—授权—交易—维权"全链路服务。作品文件在浏览器本地计算 SHA-256 指纹后写入以太坊测试链（Sepolia），原件不出本地，链上仅存哈希摘要与权属记录，天然保护隐私且不可篡改。平台实现了四类授权方式（个人欣赏/商用/改编/独家买断）由作者多选开放、独立定价；独家买断成交后版权自动转移至买家仓库并由其自主决定二次上架；内置积分体系（签到、点赞、收藏获取，可兑换个人欣赏授权）与 ETH 双轨支付；买卖双方配有议价消息中心与作者自动回复；同时提供管理员后台完成作品审核、用户管理、交易监控与审计日志。前端采用原生 HTML/CSS/JS + ethers.js 直连区块链，无需后端即可完整运行。

------------------------------------------------
二、开源代码与组件使用情况说明
------------------------------------------------
本项目代码为团队自主编写，未使用整站级开源作品。使用的第三方开源组件如下：
1. ethers.js v6.13.4（MIT 许可证）：用于钱包连接（MetaMask）、交易签名与合约交互，本地化引入，不依赖 CDN；
2. 原生 HTML5 / CSS3 / JavaScript（ES2020）：界面与业务逻辑均为自主开发，未使用 Vue/React 等框架；
3. 浏览器内置 Web Crypto API（W3C 标准）：用于作品 SHA-256 指纹计算；
4. Python 3 标准库 http.server：仅作为本地静态文件开发服务器，非作品组成部分。
以上组件均为 MIT 或标准规范，使用方式符合其开源协议，本项目整体以学习与研究为目的发布。

三、作品安装说明
------------------------------------------------
方式一（在线访问，推荐）：直接打开作品部署链接 https://gui-su.github.io/chainvault-dapp/ ，使用 Chrome/Edge 等现代浏览器即可，无需安装任何软件。
方式二（本地运行）：
1. 解压作品压缩包；
2. 双击"启动网站.bat"（需已安装 Python 3），脚本会自动启动本地服务器并打开浏览器；
   也可手动执行：python server.py，然后访问 http://localhost:8123/index.html；
3. 登录方式：点击导航栏"💬 消息中心"旁的登录入口，可用邮箱账号或"演示钱包"登录（无需安装钱包插件）；安装了 MetaMask 的用户可选择钱包签名登录（切换到 Sepolia 测试网络）。
4. 测试账号见压缩包内"测试账号.txt"（管理员：admin@chainvault.io）。

五、设计思路
------------------------------------------------
1. 确权环节遵循"哈希上链、原件不出本地"原则：浏览器通过 Web Crypto 计算文件 SHA-256，仅摘要与元数据写入 CopyrightRegistry 合约，从机制上规避了中心化存储的泄露与篡改风险；
2. 授权与交易写入智能合约：个人欣赏/商用/改编/独家买断四类授权由作者多选开放并独立定价，独家买断成交后所有权链上转移并退出市场，是否二次上架由新权利人决定，还原真实版权流转逻辑；
3. 双轨支付设计：商用类授权用 ETH 结算并自动分账版税，个人欣赏授权使用可免费获取的平台积分，降低普通用户体验门槛，同时以签到/点赞/收藏激励社区活跃；
4. 沟通撮合：买卖双方内置议价消息中心，作者可设置自动回复，弥补链上交易缺乏协商环节的短板；
5. 平台治理：管理后台提供作品审核、用户封禁、交易监控与操作审计，形成完整闭环；
6. 工程上采用纯前端 + 相对路径架构，可零配置部署于 GitHub Pages 等静态托管，ethers 本地化引入保证弱网/离线环境可用。

------------------------------------------------
六、设计重点难点
------------------------------------------------
1. 浏览器安全上下文限制：SHA-256 依赖的 Web Crypto API 仅在 HTTPS/localhost 可用，通过检测 isSecureContext 降级提示，并将站点部署于 HTTPS；
2. 前端状态与事件绑定：页面为单文件内联脚本，曾出现变量暂时性死区（TDZ）导致整页事件失灵的问题，通过规范化"状态变量置于脚本顶部"与自动化 DOM 模拟测试解决；
3. 无后端的链下索引：作品、订单、消息等业务数据以 localStorage 模拟索引层，设计了一套与真实合约事件监听对齐的数据接口，便于后续替换为后端服务；
4. 钱包兼容与降级：未安装钱包时自动降级为演示钱包保证全流程可体验，ethers 本地化避免 CDN 不可达导致功能失效；
5. 授权数据结构演进：授权方式从单选重构为多选数组并兼容历史数据，涉及市场筛选、购买面板、编辑上架等多处联动。
